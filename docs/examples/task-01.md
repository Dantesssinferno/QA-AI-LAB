[AUTH] Доработка страницы регистрации и реализация функциональности восстановления пароля
Описание

Необходимо реализовать страницу регистрации нового пользователя и функциональность восстановления пароля.

Пользователь должен иметь возможность:

зарегистрировать новый аккаунт;
подтвердить корректность введенных данных;
получить письмо для восстановления пароля;
установить новый пароль по ссылке из письма;
войти в систему с новым паролем.
Бизнес-цель

Упростить процесс регистрации новых пользователей и предоставить безопасный механизм восстановления доступа к аккаунту.

User Story 2. Восстановление пароля

Как зарегистрированный пользователь

Я хочу восстановить пароль,

Чтобы снова получить доступ к аккаунту.

Экран восстановления

Поля:

Email

Кнопка:

Восстановить пароль

Логика работы

После нажатия кнопки Backend проверяет существование пользователя.

Если пользователь найден:

генерируется одноразовый токен;
токен сохраняется;
пользователю отправляется письмо.

Пользователь всегда получает одинаковый ответ независимо от существования Email.

Сообщение:

Если аккаунт существует, инструкция по восстановлению была отправлена на указанный Email.

Это необходимо для защиты от определения зарегистрированных пользователей.

API восстановления

POST

/api/auth/forgot-password

Request

{
    "email":"user@test.com"
}
Email

Письмо должно содержать ссылку

https://site.com/reset-password?token=<token>

Требования к токену

одноразовый;
срок действия 15 минут;
после использования становится недействительным.
Экран установки нового пароля

Поля

Новый пароль
Подтверждение пароля

Кнопка

Сохранить

Валидация пароля аналогична регистрации.

API смены пароля

POST

/api/auth/reset-password

Request

{
    "token":"JWT",
    "password":"Password123!"
}

После успешной смены отображается сообщение

Пароль успешно изменен.

После этого пользователь может выполнить вход новым паролем.

Требования безопасности
Пароль хранится только в виде hash.
Использовать Argon2 или BCrypt.
Старый пароль никогда не хранится.
Один токен восстановления можно использовать только один раз.
После смены пароля необходимо завершить все активные пользовательские сессии.
После пяти запросов восстановления в течение 15 минут временно блокировать возможность создания новых запросов (rate limiting).

Логирование

Необходимо логировать следующие события:

успешная регистрация;
неудачная регистрация;
запрос восстановления пароля;
успешная смена пароля;
попытка использования просроченного токена;
попытка повторного использования токена.
Acceptance Criteria
Пользователь может успешно зарегистрироваться.
Все поля проходят валидацию согласно требованиям.
Нельзя зарегистрироваться с существующим Email.
Пользователь может запросить восстановление пароля.
Пользователь получает письмо со ссылкой восстановления.
Просроченный токен не позволяет изменить пароль.
Использованный токен нельзя использовать повторно.
После смены пароля вход возможен только с новым паролем.
Старые пользовательские сессии завершаются автоматически.
Все ошибки отображаются согласно UX-дизайну.
Все действия логируются.
